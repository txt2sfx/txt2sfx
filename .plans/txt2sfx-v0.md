## 0. Что это за проект

Опенсорс-инструмент: текстовое описание звукового эффекта → **компактный процедурный
код Web Audio API** (300–1000 байт, zero-dependency), а не аудиофайл. Философия
скопирована с img2threejs — *reconstruction-by-code*.

Четыре принципа, обязательные для всех архитектурных решений:

1. **Scripts enforce, the model judges.** Парсинг, валидация, рендер, метрики, скоринг —
   детерминированный код без LLM. LLM участвует только в проектировании структуры звука
   и оценке перцептивного сходства.
2. **Spec-first, fail fast.** Кодогенерация не стартует, пока спека не прошла валидатор
   физических инвариантов. Никогда не чинить сгенерированный JS — чинится soundline,
   JS перегенерируется.
3. **Разделение структуры и чисел.** LLM проектирует топологию (слои, примитивы, роли);
   точные числа подбирает численный оптимизатор против целевого акустического профиля.
4. **Выход — читаемый текст.** Единица обмена — формат `soundline`, диффабельный.

Никаких облачных text-to-audio моделей (Stable Audio, ElevenLabs) в ядре. CLAP-судья —
опциональный плагин, в v0 достаточно интерфейса-заглушки.

### Требование заказчика по ключам и локальности

- Тестирование идёт через **Gemini по API-ключу, который вставляется прямо в плейграунде**,
  и через **Opus 5 из CLI / по API / через MCP**.
- Внешний агент пользователя должен воспользоваться библиотекой и накопленной базой
  рецептов **максимально быстро и без установки**.
- LLM всегда пользовательская; если привлекается локальная модель генерации звука —
  она тоже исполняется на машине пользователя. Ничего не проксируется через наш сервис.

## 1. Как поднять окружение на новой машине

```powershell
# требуется Node >= 20 (проверено на v24.15.0 и v25.2.1)
npm install -g pnpm@10     # см. примечание про corepack ниже
cd <repo>
pnpm install
pnpm vitest run            # 220 тестов должны быть зелёными
pnpm build                 # tsc -b packages/shared packages/core
pnpm dev                   # плейграунд на http://localhost:5173
```

Примечания:

- **Corepack удалён из Node 25**, поэтому описанный ранее обход `corepack pnpm <cmd>`
  больше не работает: бинарника `corepack` в `C:\Program Files\nodejs` просто нет.
  Рабочий способ — поставить pnpm глобально через npm (`npm install -g pnpm@10`),
  права администратора не нужны.
- В `package.json` уже прописан `pnpm.onlyBuiltDependencies: ["esbuild"]`;
  предупреждение «Ignored build scripts: esbuild» безвредно, vitest работает.
- `node-web-audio-api` — **devDependency воркспейса**, не зависимость `core`.
  Ядро получает фабрику `OfflineAudioContext` инжекцией (см. §5).
- `.gitattributes` форсит `eol=lf` — без него round-trip тесты на Windows падают.
- Типизация тестов проверяется отдельным вызовом: `tsc -b` покрывает только `src`.
  Постоянный `tsconfig.test.json` — задача фазы 7; до неё проверять одноразовым
  конфигом с `include: ["packages/*/src", "packages/*/test"]` и `paths` на
  `@txt2sfx/{shared,core}` → `src/index.ts`.

## 3. Замороженные решения (не переоткрывать без причины)

Все они уже отражены в коде; при написании `docs/SOUNDLINE_GRAMMAR.md` их надо перенести
в документацию.

1. **Заголовок:** `sound "<имя>" <длительность> [<категория>] [loop]`.
   Категория — из закрытого списка `pop|ui|laser|impact|explosion|pickup|foley|cycle|misc`;
   без неё валидатору фазы 3 не к чему привязать инварианты. `misc` — дефолт, при
   сериализации опускается. `loop` — отдельный флаг; категория зациклённых звуков `cycle`
   (валидатор фазы 3 требует для неё флаг `loop`).
2. **Сигнальный порядок:** `source → envelope → chain → mix`, хотя пишется
   `source >> chain | envelope`. Огибающая шейпит источник, эффекты идут после неё,
   поэтому хвосты `delay`/`verb` переживают `decay`. На этом построен helicopter
   (ротор = сабовый удар, рециркулированный delay-петлёй; LFO в v0 нет).
   **Компилятор фазы 2 обязан следовать этому порядку.**
3. **Числа хранятся как написаны** (`1.2kHz` = 1.2 + unit `kHz`), конвертация только
   через `toHz/toMs/toLinear`. Это и даёт lossless round-trip.
4. **Слитные безразмерные параметры** (`Q6`) — только для закрытого набора имён из
   сигнатур (kind `ratio`/`level`). Поэтому слой `snap2` остаётся одним идентификатором.
   Сериализатор склеивает только односимвольные имена в верхнем регистре (`Q6`),
   остальное через пробел (`gain 0.9`).
5. **Ошибки построчные:** одна сломанная строка не прячет остальные
   (`parseWithDiagnostics`). Лексические ошибки прерывают разбор целиком.
   Формат сообщения: `line L, col C: <detail> (<hint>)` — идёт в LLM как есть.
6. **Словарь синонимов в подсказках** (`lowpass→lp`, `reverb→verb`, `sweep→chirp`,
   `release→decay`, `volume→gain`, ...) + Дамерау-Левенштейн для опечаток
   (`nosie→noise`). Расстояние `lowpass`→`lp` = 5, чистая метрика такое не ловит,
   а LLM ошибается именно так. Каждый пойманный синоним экономит итерацию агента.
7. **В AST попадают только явно написанные аргументы**; дефолты применяет компилятор.
   Иначе round-trip перестаёт быть побайтовым.
8. **Канонизация:** 2 пробела отступа слоя, аргументы в порядке сигнатуры, огибающая
   в порядке `gain attack hold decay curve delay`, комментарии сохраняются
   (файловые, построчные над слоем и хвостовые), пустые строки съедаются.

## 5. Фаза 2 — примитивы, компиляция, рендер, кодоген (готово)

### 5.1. Главное решение: промежуточное представление вместо двух бэкендов

ТЗ предполагало, что `graph.ts` собирает живые узлы, а `codegen.ts` независимо печатает
строки. Это означало бы **две реализации одного DSP** — 8 примитивов и 6 эффектов,
написанных дважды и обязанных совпадать до сэмпла. Они бы разошлись.

Поэтому DSP живёт в одном месте. Введён `compile/ir.ts` — `AudioIR`, описание графа,
независимое от sample rate и от наличия аудиостека. Примитивы и эффекты эмитят IR;
оба бэкенда — тупые проигрыватели: `graph.ts` инстанцирует, `codegen.ts` печатает.
Тест паритета проверяет **два проигрывателя**, а не две копии синтеза, — и потому
может требовать не «совпадения RMS в пределах допуска», а **побайтового равенства
рендеров**. На всех 10 примерах `maxAbsDiff === 0`.

Следствия, важные для следующих фаз:

- `PrimitiveDef.build(args, ctx)` вместо `build(ctx, args, when, durationMs)`:
  `BuildContext` несёт `ir`, `seed`, `start`, `stop`. Никакого `AudioContext`.
- Времена в IR — секунды **относительно онсета звука**; `when` добавляет бэкенд,
  потому что экспортируемая функция принимает его аргументом.
- `quantizeIR` округляет все числа до 6 знаков после запятой. Это не косметика:
  без округления экспорт нёс бы `0.191891363534` и либо распухал, либо округлял —
  а округлённая длина буфера в экспорте сдвигает все сэмплы относительно эталона.
  Округление один раз, до обоих бэкендов, и есть причина, по которой паритет точный.

### 5.2. Отклонения от ТЗ и их причины

| Что | ТЗ | Сделано | Почему |
| --- | --- | --- | --- |
| `modal` | 2–5 биквад-резонаторов | аддитивный синтез в буфер | Уровень резонатора, возбуждённого бёрстом, не предсказуем из soundline, а непредсказуемый уровень источника ломает инвариант `peak ≤ 0.95`, под который откалиброваны примеры. Акустика та же: партиал звенит на `freq * ratio`, затухает с `tau = Q/(pi*f)`; сумма делится на сумму амплитуд, поэтому пик буфера **доказуемо ≤ 1**. |
| `click` | «одиночный импульс» | оконный шумовой бёрст | Дирак не несёт энергии при разумном gain, униполярный «бугор» — это DC-удар, смещающий все замеры пика ниже по конвейеру. Бёрст широкополосен, имеет нулевое среднее, и `width` делает ровно то, что обещает грамматика: шире = больше низа = глуше. |
| PRNG | «свой seeded PRNG» | MINSTD (`s*16807 % 2^31-1`) | Лучше 32-битного LCG (полный период, нет слабых младших битов) **и** короче в экспорте: не нужен `Math.imul`, так как `2^31 * 16807 < 2^53`. 17 байт экономии в каждом из четырёх генераторов. Состояние не должно достигать 0 — за это отвечает `normalizeSeed` в `IRBuilder.buffer()`. |
| `pluck` | KS-петля или предрасчёт | предрасчёт буфера | Как и разрешало ТЗ: экспорту не нужны `DelayNode`, петля обратной связи и её обвязка. |

Прочие принятые решения (обоснования — в TSDoc соответствующих файлов):

- Порядок сигнала `source → envelope → chain → mix` соблюдён; хвосты `delay`/`verb`
  переживают `decay` и учитываются в `soundDurationMs` (`compile/duration.ts`).
- Атака всегда линейная (экспонента не может начинаться с нуля, а старт не с нуля щёлкает);
  спад по умолчанию экспоненциальный до `GLOBAL_LIMITS.minExpTarget` — **абсолютного**
  порога -60 dBFS, а не относительного, иначе тихие слои затухали бы дольше громких.
- Все экспоненциальные рампы клампятся от нуля (`safeExpTarget`), в том числе когда
  модель пишет `-> 0Hz` или `index -> 0`: намерение слышимо, литеральный ноль — нет.
- `dist`/`delay`/`verb` при `mix 0` не строят wet-путь, при `mix 1` — не строят
  сумматор. Оба края встречаются (`mix 1` — это helicopter), каждый сэкономленный
  узел стоит байтов в экспорте.
- Сиды слоёв разведены умножающим хешем по индексу слоя: два слоя белого шума с общим
  сидом дали бы не более широкую текстуру, а на 6 дБ громче ту же.
- Рендер **сообщает** о клиппинге (`clipped`), но никогда не нормализует: нормализация
  спрятала бы проблему там, где её ещё можно починить правильно — в спеке (принцип 2).

### 5.3. Замеренные пики: правка примеров не потребовалась

ТЗ предупреждало, что в `explosion` сумма gain четырёх слоёв ≈ 1.63, и требовало
подкрутить gain по факту замера. Замер (seed по умолчанию, 44.1 kHz):

| пример | пик | пример | пик |
| --- | --- | --- | --- |
| bubble-pop | 0.859 | helicopter | 0.505 |
| coin | 0.498 | laser | 0.818 |
| door-creak | 0.283 | powerup | 0.418 |
| explosion | 0.744 | sword-clash | 0.436 |
| footstep-gravel | 0.355 | ui-click | 0.397 |

Клиппинга нет ни в одном примере: слои не выходят на пик одновременно — их разводят
разные атаки, спады и `delay`. Сумма gain — не верхняя граница пика; **и не нижняя**:
`hp` дифференцирует, поэтому фильтр может поднять пик выше входного (есть отдельный
тест, фиксирующий это). Отсюда практический вывод для фазы 3: инвариант `maxPeak`
проверяется только на рендере, аналитически из спеки он не выводится.

Осторожно при работе над фазой 4: у `explosion` запас всего ~2 дБ, и оптимизатор,
крутящий слоты, может его съесть. Пик стоит считать частью fitness или хотя бы
проверять после оптимизации.

### 5.4. Размер экспорта: 1 KB достигнут не для всех примеров

`GLOBAL_LIMITS.maxExportBytes` = 1024. Фактические размеры после оптимизации эмиттера:

| пример | слоёв | байт | | пример | слоёв | байт |
| --- | --- | --- | --- | --- | --- | --- |
| coin | 2 | **531** | | helicopter | 3 | 1093 |
| laser | 2 | **553** | | powerup | 3 | 1169 |
| ui-click | 2 | **811** | | door-creak | 3 | 1185 |
| bubble-pop | 2 | **824** | | explosion | 4 | 1458 |
| | | | | sword-clash | 3 | 1579 |
| | | | | footstep-gravel | 3 | 1708 |

**Все четыре двухслойных примера укладываются в 1 KB; трёх- и четырёхслойные — нет,
превышение от 7% до 67%.** Причина структурная, а не в небрежной генерации: фиксированную
стоимость составляют процедурные генераторы буферов, и это ровно та цена, за которую
проект не тащит ни одного ассета. `footstep-gravel` платит за генератор шума (два цвета),
модальный банк и кривую вейвшейпера сразу — ~640 байт до первого узла графа.

Что уже сделано для размера (снизило пики размеров на 15–25%): один общий `const` на всю
прелюдию (легально — список `const` инициализируется слева направо); генераторы шума
эмитятся **по фактически использованным цветам**; односимвольные алиасы для длинных имён
методов `AudioParam`, для `connect`, для пары `start`/`stop` и для повторяющихся фабрик
`ctx.createX()` — каждый только когда окупает собственное объявление; значения, равные
дефолтам Web Audio (`gain` 1, `Q` 1, синусный осциллятор), не пишутся вовсе; параметр
с единственным `set`-событием пишется как `.value=`.

Дальнейшие идеи исчерпаны: цепочки `a.connect(b).connect(c)` дают ~3 байта на звено,
общий envelope-хелпер сэкономил бы ~20 байт на слой, но закодировал бы форму огибающей
во втором месте и обрушил бы то самое свойство, из которого следует точный паритет.

**Решение:** `withinBudget` — это отчёт, а не запрет. `codegen` возвращает `bytes` и
`withinBudget`, но всегда отдаёт полный работающий код: молча урезать экспорт или
отказаться его выдавать было бы хуже, чем сказать вызывающему, сколько он стоит.
В тестах зафиксированы (а) потолок размера на каждый пример как защита от регрессий и
(б) требование `withinBudget` для всех сооружений в ≤ 2 слоя. Для README (фаза 7) честная
формулировка — «300–1000 байт для типичного SFX», а не «всегда меньше килобайта».

### 5.5. Ещё один вход для фазы 3

`helicopter` реально звучит **4046 мс** при заявленных в заголовке 1500: `delay 90ms`
с `feedback 0.88` спадает до -60 дБ за 54 повтора. Это не баг рендера, а именно тот
случай, который валидатор фазы 3 обязан поймать по контракту длительности заголовка.
`soundDurationMs(ast)` уже возвращает 4046 и готов к использованию как есть.
Оценка хвоста ограничена сверху 4000 мс на эффект (`delay.ts`), чтобы `feedback 0.95`
не просил минуту аудио; правду при этом сообщает валидатор, а не гигантский буфер.

### 6.1. Валидатор: правила и решения

11 правил в `INVARIANTS` (массив, чтобы фаза 7 могла добавлять свои), два входа:

- `validate(ast)` — всё, что выводится из текста;
- `validateRender({ peak })` — только то, что нельзя вывести (§5.3). Отдельный тип
  `RenderFacts`, а не `RenderResult`: у оптимизатора и плейграунда есть пик без
  `AudioBuffer`, а анализатору надо уметь давать те же числа по декодированному
  референсу.

Идентификаторы правил: `<cat>.{min,max}-duration`, `<cat>.max-layer-decay`,
`<cat>.max-freq-ramp`, `<cat>.max-layers`, `cycle.requires-loop`, `duration.contract`,
`envelope.attack-longer-than-voice`, `param.range`, `param.slot-range`,
`ramp.exp-to-zero`, `pop.rising-resonance`, `peak.max`, `peak.silent`.

Принятые решения:

1. **Severity по величине отклонения** — у контракта длительности и у
   attack-vs-voice. Оба сравнивают с *оценкой*, а не с замером: хвост — экспонента,
   приведённая к -60 дБ, хвост эффекта — формула с потолком 4 с. Пара процентов —
   это шум оценки, а не ложь; в два раза — уже другой звук. Порог: слack
   `max(10 мс, 5 %)` — чисто; до 25 % — `warn`; свыше — `error`.
2. **`param.range` — error, хотя границы в сигнатурах названы «soft».** «Soft»
   описывает происхождение чисел (вкус и практика), а не серьёзность нарушения.
   `Q 400` на биквадре звенит колоколом, осциллятор на 19 кГц не слышен половине
   аудитории, а warn, который цикл агента вправе проигнорировать, стоил бы итерации
   на то же самое открытие.
3. **Исключение: `-> 0` в конце рампы не считается выходом за границу.**
   `-> 0Hz` и `index -> 0` — поддержанная идиома «свести в ничто», компилятор
   специально клампит экспоненту от нуля (§5.2), и `ramp.exp-to-zero` уже говорит,
   что реально произойдёт, лучше, чем жалоба на диапазон. Голова рампы с нулём —
   по-прежнему error. Тест на отсутствие двойного отчёта есть.
4. **`param.slot-range` — warn.** Слот, выходящий за границу параметра, — это
   разрешение оптимизатору генерировать невалидный звук; узнать об этом лучше здесь,
   чем в фазе 4 через тысячу кандидатов. Но seed легален и звук рендерится, поэтому
   не error.
5. **`peak.silent` (warn, порог 0.02 ≈ -34 dBFS) добавлен сверх ТЗ.** Ровно тот
   класс провала, который §11 назвал самым дорогим: слой на -41 дБ без единой
   ошибки. Рецепт, рендерящийся в тишину, не бывает тем, что просили.
6. **Только перерасход контракта, не недобор.** Заголовок на 1500 мс при 40 мс
   звука — тоже ложь, но ТЗ просило ловить выход за контракт, а не недоиспользование;
   отдельного правила нет сознательно.

### 6.2. Два примера не проходят валидацию — и это правда, а не баг правил

8 из 10 рецептов чисты. Два — нет, оба по `duration.contract`:

| рецепт | заявлено | реально | перерасход | severity |
| --- | --- | --- | --- | --- |
| helicopter | 1500 мс | 4046 мс | 170 % | **error** |
| sword-clash | 700 мс | 821 мс | 17 % | warn |

`helicopter` — тот самый предсказанный §5.5 случай. Важно: **его нельзя привести в
контракт правкой одного заголовка** — 4046 мс выходит за собственный потолок категории
`cycle` (3000 мс). Находка зафиксирована тестом, а не заглажена: это решение звукового
дизайна, а не рефакторинг.

**Три рычага, решение за заказчиком:**

1. Принять как есть — тест это пинует, сюрприза не будет.
2. Менять DSP: `delay 90ms feedback 0.88` — это и есть ротор (§3.2); чтобы хвост
   уложился в 1450 мс, нужен `feedback ≤ 0.65`, то есть другой звук.
3. Поднять `CATEGORY_LIMITS.cycle.maxDurationMs` с 3000 до ~4500 и заголовок до 4046.
   Законный вариант: шапка `constants.ts` прямо называет эти числа мнением проекта, а
   обоснование «редко превышают три секунды» — про период петли, не про хвост
   рециркуляции. Если 4-секундный разгон ротора и есть правильный звук, сдвинуть
   границу дешевле, чем портить рецепт.

**Дедлайн решения — фаза 5, не конец работ.** `POST /api/recipes` по §8 валидирует
soundline перед записью, а `seed.ts` заливает все `examples/*.soundline`. Если сидер
уважает валидацию, helicopter в банк не попадёт: 9 рецептов вместо 10, и `retrieve`
по «helicopter»/«rotor» вернёт пустоту — то есть банк перестанет показывать, что умеет
отдавать зациклённые текстуры. Фазе 4 helicopter не нужен: тест восстановления слотов
делается на любом рецепте, и брать заведомо внеконтрактный в фикстуры не стоит.

Заодно проверено и зафиксировано, что для `loop`-звука хвост эффекта **считается**:
заявленная длительность зациклённого звука — это период петли, а буфер на 4046 мс
даёт цикл в 2.7 раза длиннее обещанного, то есть шов слышен.

### 6.3. Анализатор: отклонения от ТЗ

| Что | ТЗ | Сделано | Почему |
| --- | --- | --- | --- |
| метрика | один `profileDistance` = поля + STFT loss | `profileDistance` (поля), `stftDistance` (волны), `soundDistance` (оба, 50/50) | STFT loss невозможно посчитать из `SoundProfile`: профиль — 100 чисел, лоссу нужно аудио. При этом банк рецептов хранит только профили, и retrieve обязан сравнивать рецепты, ничего не рендеря. Одна функция не может обслужить оба вызова. |
| STFT loss | log-magnitude L1 | L1 по log-magnitude **плюс spectral convergence**, 50/50 на каждый кадр | L1 в одиночку размывается бинами, где оба сигнала на полу, а в разреженном спектре это почти все бины: синус 1 кГц против синуса 1.4 кГц — ничего общего — давал **0.046**, потому что шесть бинов с разницей 100 дБ усреднились по 250 бинам, согласным насчёт тишины. (б) Среднее с радиусом ±4, включающее сам пик, сжимало метрику — чисто тональные рецепты давали 0.64 вместо ~0. После правок: тональные 0.00–0.04, шумовые 0.31–0.81. |

FFT свой, radix-2, twiddle-факторы вращением, а не `Math.cos` на бабочку. `peakHz`
уточняется параболической интерполяцией по логарифмам: бин 512-го окна — 86 Гц, а
различать надо 1055 против 1098 (§9.2), то есть полбина. Проверено на синусах:
ошибка < 21 Гц на 1055/1098/3210 Гц.

Мини-FFT плейграунда (`apps/web/src/lib/fft.ts`) сознательно **не** переиспользован,
как и требовал §9.1.

### 6.4. Найден и исправлен баг детектора онсета — в анализаторе и в плейграунде

«Самый крутой подъём» искался с кадра 1. У звука, у которого все слои с
`attack 0ms`, подъёма нет вообще: сигнал начинается на полной амплитуде на сэмпле 0,
и каждый следующий кадр тише предыдущего. Максимальный «подъём» тогда равен нулю и
находится в хвостовой тишине, которую рендерер всегда дописывает, — онсет уезжает
за конец звука, а весь профиль обнуляется. Ни ошибки, ни предупреждения.

Исправлено в `packages/analyzer/src/profile.ts` (кадр 0 сравнивается с неявной
тишиной перед сигналом) и тем же однострочником в `apps/web/src/lib/analysis.ts`,
где была ровно та же формула, — иначе Compare-панель ломалась бы на любом рецепте
из одних `attack 0ms`. Регрессионный тест зафиксирован.

| кандидат | вектор пишется обратно **в AST** | вектор пишется в **текст**, затем `parse` | (а) Измеряется ровно то, что будет отгружено: рецепт пишется с точностью `roundLiteral`, и поиск по полным float'ам с округлением в самом конце отдал бы рецепт, который никто не рендерил. Кривая та же, что у слайдеров плейграунда. |

`stallGenerations` = 20 (треть бюджета), а не 12: замерено на 3-мерном Растригине —
порог 12 останавливал поиск на вдвое большей ошибке, чем тот же прогон, которому
позволили продолжить. Плато в десяток поколений — рядовая середина поиска, а не
вердикт. Цена ошибки асимметрична: ложный «stalled» отправляет LLM переделывать
топологию, которую переделывать не надо.

`roundLiteral` вынесен в `@txt2sfx/core` (`grammar/units.ts`) и используется и
оптимизатором, и слайдерами плейграунда: два приватных экземпляра этой таблицы
рано или поздно разошлись бы в том, как пишется одно и то же число.

### 7.2. Найден баг: `getChannelData` отдаёт представление в нативной памяти

Первый прогон сквозных тестов **убил воркер vitest** без JS-стека, а до этого
`stftDistance` начал возвращать NaN на сигналах, в которых за мгновение до этого
не было ни одного нечисла.

Причина: `node-web-audio-api` возвращает из `getChannelData(0)` вид на память,
которой владеет нативный контекст. Оптимизатор держит `target.signal` живым через
сотни рендеров; контексты этих рендеров становятся недостижимы, GC их собирает — и
освобождает буфер под видом, который всё ещё держит цель. Сэмплы превращаются в NaN,
любая метрика с этой целью становится NaN (а `NaN <= x` — ложь, поэтому DE не
принимает ни одного кандидата и «лучшим» остаётся seed), затем процесс падает.

Исправлено копированием на выходе из аудиостека — `Float32Array.from(...)` — в
хелперах тестов оптимизатора и анализатора. **Важно для фазы 5:** `seed.ts` рендерит
десять рецептов и снимает профили, то есть окажется ровно в этой же позиции. Всё, что
держит сэмплы дольше контекста, обязано копировать.

### 9.1. Фаза 6a — локальный плейграунд (готово, вынесен вперёд фаз 3–5)

Причина переноса: без интерактивного прослушивания качество примеров не доводится, а
работа через файлы и ручной рендер в WAV — слишком долгий цикл. Промпт-бар и поле
Gemini-ключа осознанно **не** сделаны: они требуют `packages/agent` (фаза 7) и валидатора
(фаза 3), без которого LLM будет уверенно выдавать нерабочий soundline. Всё остальное из
§9 закрыто, и это ровно та часть, которой не нужен ключ.

**Файлы:** `apps/web/` — `index.html`, `vite.config.ts`, `plugins/examples-fs.ts`,
`src/{main.tsx,App.tsx,styles.css}`, `src/lib/{examples,slots,engine,fft,highlight}.ts`,
`src/components/{Editor,Diagnostics,Gallery,Sliders,Timeline,Visualizer,ExportPanel}.tsx`.
Vite 5 + React 19 + TS, алиасы на `src/index.ts` пакетов (как в `vitest.config.ts`).

Ключевые решения, которые не стоит переоткрывать:

- **Источник истины — текст в редакторе.** Слайдеры не мутируют AST, а перезаписывают
  спан `NumberLiteral.loc` в исходнике. Важно: этот `loc` покрывает только числовой токен
  (`3200Hz`), без `~` и `[500..8000]`, поэтому рамка слота остаётся на месте, а редактор
  всегда показывает то, что звучит. После каждой правки офсеты сдвигаются — значит
  переспарсить и пересобрать список слотов до следующего изменения.
- **Два пути воспроизведения.** Play — живой граф через `buildGraph` (тот же путь, что у
  экспортируемого кода); Loop — офлайн-рендер через зацикленный `AudioBufferSourceNode`,
  потому что `cycle`-звук иначе не оценить, а зацикливание живого графа даёт шов на стыке.
- **Картинки рисуются по офлайн-рендеру, не по `AnalyserNode`** — изображение соответствует
  рецепту, а не моменту, и есть до нажатия Play.
- **Ось частот логарифмическая**, слайдеры частот и времён — тоже (`lib/slots.ts`):
  на линейной шкале `[500..8000]` вся полезная нижняя часть умещается в 5 % хода.
- **Запись в `examples/` только в dev** (`apply: 'serve'`, имя строго `[a-z0-9-]+`,
  каталог только `examples/`, перевод CRLF→LF из-за `.gitattributes`). Список рецептов в
  dev берётся с этого же эндпоинта, а не из `import.meta.glob`: glob — снапшот времени
  сборки и не видит только что сохранённый файл. HMR для glob-модуля намеренно
  проглатывается (`import.meta.hot.accept`), иначе Save вызывает full reload и убивает
  несохранённые буферы.
- **Save под другим именем = «сохранить копию»**: буфер исходного рецепта остаётся
  грязным, ничего не теряется молча.
- Свой мини-FFT в `src/lib/fft.ts` **не** переиспользовать в фазе 3: у анализатора другие
  требования (детерминизм, Node, `SoundProfile`), общая «утилита» испортит обоих.

Что осталось от §9 на фазу 7: промпт-бар, выбор провайдера, поле ключа и галерея из
банка вместо `examples/`. `CompareView` сделан — см. §9.3.

### 9.2. `bubble-pop` переписан под референс

Заказчик указал эталон — `C:\Projects\games\block_chpok\src\pop1.mp3` (игровой хлопок
пузыря) — и сообщил, что пресет на него не похож. Замер объяснил, почему.

| метрика (в момент хлопка) | референс | старый пресет | новый |
|---|---|---|---|
| доминирующая частота | 1055 Гц | **97 Гц** | 1098 Гц |
| центроид | 1400 Гц | 960 Гц | 1250 Гц |
| полоса 0.8–2 кГц | −3 дБ | −1 дБ | −2 дБ |
| полоса 2–6 кГц | −23 дБ | −31 дБ | −19 дБ |
| спад, дБ за 5 мс | 0/−2.8/−9.1/−16.6/−20.7 | 0/−7/−21.7/−34/−38 | 0/−1.6/−9.1/−16.9/−24.3 |

Диагноз: старый рецепт вёл частоту **вниз** (`tone sine 480Hz -> 80Hz`) и вся энергия
садилась на 97 Гц — глухой стук вместо хлопка. Референс делает наоборот: одиночная
резонансная частота ползёт **вверх** 960 → 1109 Гц за 8 мс (модель Миннарта: резонанс
каверны растёт по мере схлопывания), спад ≈1.2 дБ/мс, энергия сосредоточена в 0.8–2 кГц.

Важно для методики: «кластер партиалов 896/982/1060 Гц» в замере с окном 2048 сэмплов
(43 мс) — артефакт. Окно накрывало весь хлопок и смазало один скользящий тон в три
пика. С окном 512 картина однозначна. **Для транзиентов измерять коротким окном.**

Новый рецепт — два слоя, 876 Б: `tone tri` со свипом 700 → 1120 Гц под `lp 2200Hz`
(треугольник даёт нужные −20 дБ в полосе 2–6 кГц, синус давал −51 дБ и звучал ватно)
плюс `click 1ms` через `bp 2800Hz` на кромку. Отдельный низкий слой убран: он стоил
195 Б и выводил экспорт за потолок 900 Б, а его вклад в референсе объясняется ранней
частью того же свипа.

Не воспроизведено сознательно: у референса есть ~150 мс хвоста комнаты (−28 дБ,
≈1 кГц). В контракт `pop` (≤60 мс) он не влезает и является свойством помещения, а не
пузыря — это работа ревербератора движка. Вариант с `verb 170ms mix 0.3` проверен
(1224 Б, 10 узлов, категория `misc`) и лежит вне `examples/`, потому что тест
`render.test.ts` фиксирует ровно 10 рецептов.

### 9.3. Compare view — сравнение с референсом в плейграунде

**Файлы:** `src/components/Compare.tsx`, `src/lib/{analysis,draw}.ts`, `spectrumAt` в
`src/lib/fft.ts`. Референс загружается через file-picker или drop, декодируется в
браузере, живёт **только в памяти вкладки** — файл пользователя никуда не копируется.

Решения, без которых панель была бы бесполезной:

- **Выравнивание по онсету включено по умолчанию.** Записанный референс начинается
  когда включили запись, а не когда случился звук: в эталонном `pop1.mp3` хлопок стоит
  на 125 мс за тихим пре-роллом. Без выравнивания diff показывает картину сдвига, а не
  разницу звуков. Онсет ищется как **максимальный подъём** 1-мс RMS-огибающей, потом
  откат к «подножию» транзиента и уточнение до сэмпла. Порогом искать нельзя — порог
  цепляется за пре-ролл и выравнивает два звука по шуму комнаты.
- **Нормировка пиков тоже по умолчанию.** Референс 0.98 против рендера 0.79 — это
  постоянные 1.8 дБ по всему полю, они топят спектральную разницу, которая и нужна.
- **Декодирование в `OfflineAudioContext` на `GLOBAL_LIMITS.sampleRate`.** Платформа
  сама пересемплирует 48 кГц референс к 44.1 кГц рендера, и спектрограммы можно вычитать
  бин к бину. Иначе сетки бинов не совпадают.
- **Три режима:** `stacked` (кандидат над референсом), `overlay` (огибающие в одной
  панели — там наложение реально помогает) и `diff` (знаковая разница, расходящаяся
  палитра). Палитра diff — циан/янтарь, а не красный/зелёный: картинку должен уметь
  прочитать любой читатель, включая дальтоника и vision-модель.
- **Переключатель окна `full` / `zoom`.** Хвост комнаты у референса длиннее кандидата в
  5 раз и на общей оси сжимает исследуемые первые 40 мс в полоску у левого края.
- **Канвас самодостаточен:** в шапке имена обоих сигналов, режим и состояние
  выравнивания/нормировки, в diff — легенда направления. Картинка, которую нельзя
  прочитать без окружающего UI, бесполезна ровно в тот момент, когда её скопировали.
  `Copy PNG` / `Save PNG` дают 1761×579 (~70 КБ), `Copy numbers` — markdown-таблицу
  метрик; для vision-модели полезно отдать и то и другое.
- Метрики считаются в окне **512 сэмплов (~12 мс)** у собственного онсета каждого
  сигнала — см. предупреждение из §9.2 про смазывание длинным окном.

Сверка с офлайн-замерами сошлась: панель находит онсет референса на 124.7 мс (вручную
было 125) и даёт спад 0/−3/−9/−17/−21/−30 дБ (вручную 0/−2.8/−9.1/−16.6/−20.7/−30.0).

`lib/draw.ts` — общий слой рисования для `Visualizer` и `Compare`: палитра, лог-ось,
осциллограмма. Иначе суждение, сложившееся в одной панели, не переносится в другую, а
это и есть смысл сравнения.

   - `seed.ts` рендерит и профилирует рецепты, то есть держит сэмплы дольше их
     контекстов — **обязан копировать** (§7.2, иначе NaN и падение процесса);
   - `POST /api/recipes` валидирует перед записью, а `helicopter` даёт error, —
     дедлайн решения из §6.2 наступает тут;
   - профили для `profile_json` берутся из `extractProfile`, а `retrieve` в v0 ранжирует
     по FTS: `profileDistance` работает по одним профилям и без аудио, так что
     embedding-поиск при замене будет иметь чем мерить.
4. **Фаза 6, остаток** (§9): промпт-бар, выбор провайдера Gemini/Anthropic/mock, поле
   Gemini-ключа (в памяти вкладки, без localStorage), галерея из банка вместо `examples/`.
   Технически это тонкий слой поверх `packages/agent`, поэтому идёт в паре с фазой 7.
5. **Фаза 7 — агент, бенчмарк, docs, CI** (§10). Внутри — свой порядок: сначала
   `packages/agent` (он закрывает пункт 4), затем `bench/`, затем `docs/` и CI.
   При написании docs перенести туда §3 (грамматика), §5.1–5.2 (архитектура, примитивы).
